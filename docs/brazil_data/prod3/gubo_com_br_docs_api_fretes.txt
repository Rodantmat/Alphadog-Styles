Fretes
Cotação com preço final, transportadora exata, mais barata ou mais rápida, prazos e limites.
Copiar em Markdown

Cote o frete antes de criar o pedido e escolha a transportadora: um serviço exato, o mais barato ou o mais rápido. Os preços já são os preços finais da Gubo, iguais aos cobrados no pedido.

Rota	Escopo	Para quê
GET /fretes/servicos	qualquer	Lista os serviços de transporte (códigos para entrega.servico)
POST /fretes/cotacoes	fretes:cotar	Cota o frete para um CEP e uma lista de itens
GET /fretes/cotacoes/{id}	fretes:cotar	Consulta uma cotação
Como o frete é escolhido
#

O bloco entrega é o mesmo na cotação e no pedido. A cotação mostra a escolha que o pedido faria. Use um destes caminhos:

Você envia	A Gubo escolhe	frete.regra
"servico": "jadlog"	Exatamente esse serviço	servico_definido
"preferencia": "mais_barata"	O menor preço	mais_barata
"preferencia": "mais_rapida"	O menor prazo	mais_rapida
"prometida_ate": "2026-10-30"	O mais barato que entrega até a data. Se nenhum chega, o mais rápido	mais_barata_no_prazo ou prazo_em_risco
nada	O mais barato	mais_barata
Empates: no mais barato vence o menor prazo. No mais rápido vence o menor preço.
servico e preferencia não andam juntos (422 validacao, código conflito). Para dizer o que fazer se o serviço não estiver disponível, use se_indisponivel.
prometida_ate pode acompanhar qualquer caminho. Com servico ou preferencia, ela só marca prazo_em_risco.
Quando o serviço escolhido não atende o CEP
#

Nem todo serviço atende todo CEP ou todo pacote. se_indisponivel decide o que acontece:

se_indisponivel	Resultado
pendencia (padrão)	O pedido fica pendente com a pendência servico_indisponivel. Nada é cobrado
mais_barata	A Gubo usa o mais barato. frete.regra = mais_barata
mais_rapida	A Gubo usa o mais rápido. frete.regra = mais_rapida

Para saber se houve troca, compare frete.servico_codigo com o entrega.servico que você enviou.

"entrega": { "servico": "correios-sedex", "se_indisponivel": "mais_barata" }
Prazos
#

prazo_total_dias_uteis = 7 dias úteis de produção + o prazo da transportadora. A previsao_entrega conta a partir de hoje, em dias úteis, no fuso de São Paulo. No pedido, a previsão conta a partir do pagamento.

/fretes/servicos
#

Os serviços que a Gubo usa hoje. Guarde os códigos. Não é preciso consultar a cada pedido.

Hoje: correios, correios-sedex, jadlog, jet, loggi, pax, gfl e imile. A lista pode crescer. Use sempre o que a rota devolver.
Serviço com ativo: false foi desativado pela Gubo. Enviá-lo devolve 422 servico_inativo.
Código que não existe devolve 422 servico_desconhecido, com sugestões em erro.detalhes.sugestoes.
No modo teste, sem serviços reais publicados, aparecem os serviços de exemplo gubo-teste-economico, gubo-teste-padrao e gubo-teste-expresso.

Campo	Descrição
situacao	pronta, pendente (ainda calculando), falhou ou expirada
valida_ate	30 minutos após o cálculo
opcoes[]	Todas as opções disponíveis, com preço final e prazos
recomendacoes	O serviço mais barato, o mais rápido e o mais barato que cumpre prometida_ate
escolha	O que um pedido com esta mesma entrega usaria agora
sem_escolha	Quando não há escolha: { codigo: "frete_indisponivel" | "servico_indisponivel", mensagem }
dentro_do_prazo	Só com prometida_ate: true se a previsão cumpre a data
simulada	true no modo teste com CEP de cenário

Respostas:

Status	Quando
201	Cotação pronta (normalmente em 2 a 6 segundos)
202	Ainda calculando depois de 20 s. Consulte Location respeitando Retry-After
422	validacao, itens_invalidos, itens_misturados, servico_desconhecido, servico_inativo ou limite_itens_pedido
429	limite_requisicoes ou limite_cotacoes_diario
503 cotacao_indisponivel	A transportadora não respondeu. Tente de novo após Retry-After

Dica

A mesma loja, CEP e pacote (peças, peso e valor) reaproveitam a cotação válida mais recente. A resposta chega na hora e não conta no limite diário. Você não precisa guardar cache do seu lado.

GET
/fretes/cotacoes/{id}
#

Devolve a cotação no mesmo formato. Aceita Prefer: wait=N (até 10 s) enquanto estiver pendente. Cotação de outra conexão ou de outro modo: 404 cotacao_nao_encontrada.

Cotação e pedido
#

O pedido usa o mesmo bloco entrega. Envie no pedido o que você enviou na cotação:

"entrega": { "servico": "jadlog", "se_indisponivel": "mais_barata" }
Produção: a cotação mostra o preço e o prazo para o seu cliente. O pedido cota de novo quando é processado e aplica a mesma regra. O valor costuma ser o mesmo. O que vale é o frete do pedido, antes do pagamento.
Teste: se houver cotação válida para o mesmo CEP e os mesmos itens, o pedido usa exatamente as opções dela.
O pedido criado traz o frete escolhido:
"frete": {
  "servico": "Olist Envios Jadlog", "servico_codigo": "jadlog", "transportadora": "Jadlog",
  "prazo_dias_uteis": 12, "previsao_entrega": "2026-10-27",
  "regra": "servico_definido", "prazo_em_risco": false, "simulado": false
}

Enquanto o frete não é escolhido, frete e valores são null. Veja Pedidos.

Limites
#
	Produção	Teste
Cotações por minuto, por chave	30	30
Cotações calculadas por dia, por conexão	1.000	300
Itens por cotação	50	50
Validade	30 min	30 min

Cotações reaproveitadas e simuladas não contam no limite diário. O consumo do dia está em GET /conexao (consumo_hoje.cotacoes).

Modo teste
#
CEP comum: a cotação é real, com as transportadoras da Gubo. Nada é cobrado.
CEP de cenário: cotação simulada na hora. 00000-100 devolve opcoes: [] e sem_escolha.codigo = frete_indisponivel.
