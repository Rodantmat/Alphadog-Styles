API Montink
Integração via token

Introdução

Esta documentação descreve a API pública Montink (API parceiro), que permite listar o catálogo da loja, calcular frete, importar pedidos para a dashboard (Pedidos Externos) e acompanhar o status dos pedidos.

A API utiliza requisições HTTP com payloads em JSON. Em todas as rotas é obrigatório enviar o header Authorizationtoken com o token gerado na dashboard.

Gere o token em: Dashboard → Adicionar Apps → API Montink → Conectar → Gerar token de autorização.
Base URL: https://api.montink.com
Exemplo: https://api.montink.com/products
Fluxo de compra (API parceiro)
  1. Gere o token na dashboard e envie-o no header Authorizationtoken em todas as requisições.
  2. Consulte a listagem de produtos para montar o catálogo no seu checkout/loja.
  3. Consulte o detalhe do produto para variações, imagens, estoque e preço.
  4. (Recomendado) Chame iniciar carrinho e guarde o token/id retornados.
  5. Com CEP e quantidade, chame o cálculo de frete e exiba as opções ao cliente.
  6. Envie o pedido em criar pedido (com cart_token se iniciou o carrinho antes) para gravar cliente, itens e frete.
  7. Acompanhe com detalhes do pedido ou listagem de pedidos.
  8. (Opcional) Cadastre uma URL de webhook para receber atualizações de status do pedido.
Pontos importantes
  1. O pedido importado aparece em Pedidos Externos na dashboard Montink, com status inicial waiting (Aguardando Pagamento).
  2. Formas de pagamento aceitas no create_order: pix, saldo e boleto.
  3. O preço do item é o informado em products[].price. Se omitido, a API usa o preço do catálogo Montink. A API não recalcula lucro do lojista a partir desse valor na importação.
  4. O external_order_id deve ser único por loja. Reenviar o mesmo ID retorna erro de pedido já importado.
  5. Esta API não aplica cupom da loja Montink.

Referências: Central de Ajuda · Postman

Recomendamos que a integração seja feita ou supervisionada por um desenvolvedor.

Autenticação

Todas as rotas da API parceiro exigem o header abaixo. Sem ele, a API retorna Token de Autorização não enviado.

Authorizationtoken: TOKEN_GERADO_NA_DASHBOARD
HeaderObrigatórioDescrição
Authorizationtoken Sim Token gerado em Adicionar Apps → API Montink. Validade de 1 ano; pode ser revalidado na dashboard.
Content-Type Em POST Use application/json no corpo do create_order.
Erros comuns
  • Token ausente → Token de Autorização não enviado.
  • Token inválido / vencido → Token inválido (ou mensagem equivalente).
  • Token válido, mas integração desativada → mensagem pedindo reativação na página de integrações.

Cálculo de frete

Retorna as opções de frete disponíveis para o CEP e a quantidade informados. Use no checkout antes de criar o pedido. O delivery_method_id escolhido deve ser enviado como shipping_id no create_order.

Parâmetro (path)TipoDescrição
CEPstringCEP de destino (com ou sem hífen). Ex.: 01310100.
QUANTIDADEintegerQuantidade total de unidades do pedido. Exemplo: 2 camisetas + 1 moletom = 3.
Campos da resposta
CampoTipoDescrição

Iniciar carrinho

Cria um carrinho vazio na loja autenticada e devolve id + token. Guarde esses valores e envie o token como cart_token no create_order para sobrescrever esse mesmo carrinho com cliente, itens e frete.

POST Iniciar carrinho

POST https://api.montink.com/create_cart

Não exige body. Apenas o header Authorizationtoken.

Em produção, se a rota retornar 404 Page Not Found, o endpoint ainda não está publicado nesse ambiente. O contrato abaixo é o esperado quando a rota estiver ativa (success, msg, id, token. O create_order funciona sem cart_token (cria o carrinho na hora).
Campos da resposta
CampoTipoDescrição
idintegerID do carrinho na Montink.
tokenstringToken do carrinho — enviar como cart_token no create_order.

Observação: se a integração já validar o CEP antes da chamada da API, os campos street, neighborhood, city e state podem ser preenchidos automaticamente antes do envio da requisição.
** Em cada item: envie sku ou a combinação var1/var2/var3. SKU inválido ou variações que não batem com o SKU do produto base geram erro.
SKU vs var1 / var2 / var3

Recomendação: utilize preferencialmente o sku da variação. Quando o sku for informado, a API identifica automaticamente as variações correspondentes (var1, var2 e var3). Utilize var1 / var2 / var3 apenas quando sua integração não possuir o SKU da variação.

Recomendado — com SKU (não precisa enviar var1/var2/var3):

{
  "products": [
    {
      "product_id": 5180942,
      "sku": "11003110111",
      "quantity": 1,
      "price": 89.90
    }
  ]
}

Alternativa — com variações (quando não houver SKU):

{
  "products": [
    {
      "product_id": 5180942,
      "quantity": 1,
      "var1": "G",
      "var2": "Preto",
      "var3": null,
      "price": 89.90
    }
  ]
}
Regras importantes
  1. O produto precisa estar vinculado à loja do token.
  2. Integração API Montink precisa estar ativa (token regenerado / app conectado).
  3. Pedido inicia como pagamento_status = waiting / status “Aguardando Pagamento”.
  4. O valor do pedido (valor_venda) é calculado pela API a partir de products[].price (ou preço do catálogo se omitido). Não há campo value_total no body.
  5. No create_order, o frete é cotado novamente com o CEP; shipping_id seleciona a modalidade.
  6. Resposta de sucesso inclui id (pedido Montink), token e tracking_url.

Cadastrar webhook

Registra a URL que a Montink usará para notificar atualizações de status do pedido (ex.: pós-atualização do fornecedor). A URL é salva em dados_complementares.webhook_url da integração API Montink.

POST Cadastrar URL de webhook

POST https://api.montink.com/webhook
Header
Authorizationtoken: TOKEN_GERADO_NA_DASHBOARD
Body
CampoObrigatórioTipoDescrição
webhook_url Sim string (URL) Endpoint HTTPS/HTTP que receberá o POST da Montink.
Disparo

Quando o status do pedido for atualizado (webhook do fornecedor), a Montink faz POST para essa URL com o payload do pedido (campo principal: order.status) e o header Authorizationtoken com o mesmo token da integração, para identificação.
