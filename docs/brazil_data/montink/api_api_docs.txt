      <section id="intro" class="doc-content active">
        <h1 class="section-title">Introdução</h1>
        <p>
          Esta documentação descreve a <strong>API pública Montink</strong> (API parceiro),
          que permite listar o catálogo da loja, calcular frete, importar pedidos para a
          dashboard (Pedidos Externos) e acompanhar o status dos pedidos.
        </p>
        <p>
          A API utiliza requisições HTTP com payloads em <code>JSON</code>. Em
          <strong>todas</strong> as rotas é obrigatório enviar o header
          <code>Authorizationtoken</code> com o token gerado na dashboard.
        </p>

        <div class="ok">
          Gere o token em: Dashboard → <strong>Adicionar Apps → API Montink → Conectar → Gerar token de autorização</strong>.
        </div>

        <div class="endpoint-url">
          Base URL: https://api.montink.com<br />
          Exemplo: https://api.montink.com/products
        </div>

        <h5>Fluxo de compra (API parceiro)</h5>
        <ol>
          <li>Gere o token na dashboard e envie-o no header <code>Authorizationtoken</code> em todas as requisições.</li>
          <li>Consulte a <strong>listagem de produtos</strong> para montar o catálogo no seu checkout/loja.</li>
          <li>Consulte o <strong>detalhe do produto</strong> para variações, imagens, estoque e preço.</li>
          <li>(Recomendado) Chame <strong>iniciar carrinho</strong> e guarde o <code>token</code>/<code>id</code> retornados.</li>
          <li>Com CEP e quantidade, chame o <strong>cálculo de frete</strong> e exiba as opções ao cliente.</li>
          <li>Envie o pedido em <strong>criar pedido</strong> (com <code>cart_token</code> se iniciou o carrinho antes) para gravar cliente, itens e frete.</li>
          <li>Acompanhe com <strong>detalhes do pedido</strong> ou <strong>listagem de pedidos</strong>.</li>
          <li>(Opcional) Cadastre uma <strong>URL de webhook</strong> para receber atualizações de status do pedido.</li>
        </ol>

        <h5>Pontos importantes</h5>
        <ol>
          <li>O pedido importado aparece em <strong>Pedidos Externos</strong> na dashboard Montink, com status inicial <code>waiting</code> (Aguardando Pagamento).</li>
          <li>Formas de pagamento aceitas no <code>create_order</code>: <code>pix</code>, <code>saldo</code> e <code>boleto</code>.</li>
          <li>O preço do item é o informado em <code>products[].price</code>. Se omitido, a API usa o preço do catálogo Montink. A API <strong>não</strong> recalcula lucro do lojista a partir desse valor na importação.</li>
          <li>O <code>external_order_id</code> deve ser único por loja. Reenviar o mesmo ID retorna erro de pedido já importado.</li>
          <li>Esta API <strong>não</strong> aplica cupom da loja Montink.</li>
        </ol>

        <p>
          Referências:
          <a href="https://montink.sak.com.br/integracao-da-montink-via-api" target="_blank" rel="noopener">Central de Ajuda</a>
          ·
          <a href="https://documenter.getpostman.com/view/32162527/2sAYkGJyWE" target="_blank" rel="noopener">Postman</a>
        </p>
        <p>Recomendamos que a integração seja feita ou supervisionada por um desenvolvedor.</p>
      </section>

      <section id="auth" class="doc-content">
        <h1 class="section-title">Autenticação</h1>
        <p>
          Todas as rotas da API parceiro exigem o header abaixo. Sem ele, a API retorna
          <code>Token de Autorização não enviado.</code>
        </p>
        <div class="endpoint-url">Authorizationtoken: TOKEN_GERADO_NA_DASHBOARD</div>

        <table class="table table-bordered param-table">
          <thead>
            <tr><th>Header</th><th>Obrigatório</th><th>Descrição</th></tr>
          </thead>
          <tbody>
            <tr>
              <td><code>Authorizationtoken</code></td>
              <td>Sim</td>
              <td>Token gerado em Adicionar Apps → API Montink. Validade de 1 ano; pode ser revalidado na dashboard.</td>
            </tr>
            <tr>
              <td><code>Content-Type</code></td>
              <td>Em POST</td>
              <td>Use <code>application/json</code> no corpo do <code>create_order</code>.</td>
            </tr>
          </tbody>
        </table>

        <h5>Erros comuns</h5>
        <ul>
          <li>Token ausente → <code>Token de Autorização não enviado.</code></li>
          <li>Token inválido / vencido → <code>Token inválido</code> (ou mensagem equivalente).</li>
          <li>Token válido, mas integração desativada → mensagem pedindo reativação na página de integrações.</li>
        </ul>
      </section>

      <section id="shipping" class="doc-content">
        <h1 class="section-title">Cálculo de frete</h1>
        <p>
          Retorna as opções de frete disponíveis para o CEP e a quantidade informados.
          Use no checkout <strong>antes</strong> de criar o pedido. O
          <code>delivery_method_id</code> escolhido deve ser enviado como
          <code>shipping_id</code> no <code>create_order</code>.
        </p>
        <p><span class="badge-method badge-get">GET</span> Calcular frete</p>
        <div class="endpoint-url">GET https://api.montink.com/calculate_shipping/{CEP}/{QUANTIDADE}</div>

        <table class="table table-bordered param-table">
          <thead>
            <tr><th>Parâmetro (path)</th><th>Tipo</th><th>Descrição</th></tr>
          </thead>
          <tbody>
            <tr><td><code>CEP</code></td><td>string</td><td>CEP de destino (com ou sem hífen). Ex.: <code>01310100</code>.</td></tr>
            <tr><td><code>QUANTIDADE</code></td><td>integer</td><td>Quantidade total de unidades do pedido. Exemplo: 2 camisetas + 1 moletom = <code>3</code>.</td></tr>
          </tbody>
        </table>

        <h5>Campos da resposta</h5>
        <table class="table table-bordered param-table">
          <thead>
            <tr><th>Campo</th><th>Tipo</th><th>Descrição</th></tr>
          </thead>
          <tbody>
            <tr><td><code>success</code></td><td>boolean</td><td><code>true</code> quando o cálculo foi executado.</td></tr>
            <tr><td><code>msg</code></td><td>string</td><td>Mensagem (ex.: <code>Calculo de Frete executado com sucesso</code>).</td></tr>
            <tr><td><code>shipping_options</code></td><td>object</td><td>Modalidades indexadas (<code>"1"</code>, <code>"2"</code>, …).</td></tr>
            <tr><td><code>shipping_options.*.delivery_method_id</code></td><td>integer</td><td>ID da modalidade — envie como <code>shipping_id</code> no create_order.</td></tr>
            <tr><td><code>shipping_options.*.name</code></td><td>string</td><td>Nome do serviço (ex.: J&amp;T Express, Correios PAC, Correios Sedex).</td></tr>
            <tr><td><code>shipping_options.*.value</code></td><td>string</td><td>Valor do frete (ex.: <code>"29.44"</code>).</td></tr>
            <tr><td><code>shipping_options.*.business_days</code></td><td>integer</td><td>Prazo estimado em dias úteis.</td></tr>
            <tr><td><code>shipping_options.*.cnpj</code></td><td>string</td><td>CNPJ da transportadora, quando houver.</td></tr>
          </tbody>
        </table>

        <div class="note">
          Header obrigatório: <code>Authorizationtoken</code>.
          Sem quantidade no path a rota não existe (404).
        </div>

        <div class="note">
          No <code>create_order</code>, o frete é cotado novamente com o CEP do endereço;
          use o <code>shipping_id</code> retornado aqui para manter a modalidade escolhida.
          Se <code>shipping_id</code> não for enviado ou for inválido, a API usa a primeira opção disponível.
        </div>
      </section>

      <section id="createCart" class="doc-content">
        <h1 class="section-title">Iniciar carrinho</h1>
        <p>
          Cria um carrinho vazio na loja autenticada e devolve <code>id</code> + <code>token</code>.
          Guarde esses valores e envie o <code>token</code> como <code>cart_token</code> no
          <code>create_order</code> para sobrescrever esse mesmo carrinho com cliente, itens e frete.
        </p>
        <p><span class="badge-method
