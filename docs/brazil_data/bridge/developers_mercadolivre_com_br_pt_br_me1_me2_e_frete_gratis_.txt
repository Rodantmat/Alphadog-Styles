ME1 / ME2 e frete grátis


Por que definir shipping.mode = "me1" via API não exibe frete grátis no frontend mesmo com free_shipping:true no item?

Em ME1 o flag free_shipping:true pode existir nos dados, mas o Mercado Livre não o interpreta automaticamente como "frete grátis" no frontend nem aplica os benefícios automáticos do ME2. A visibilidade e os benefícios de "Frete grátis" são projetados para o ME2; para que o frontend exiba o frete grátis com os benefícios automáticos, o item deve estar no modo me2.

RECOMENDAÇÃO
Se precisar da exibição e dos benefícios automáticos de frete grátis, verifique que o item esteja no modo ME2 e atenda aos requisitos de elegibilidade do mercado.
Por que ao tentar mudar um item de ME2 para ME1 a API o deixa como not_specified?

Se a conta ou as preferências do usuário têm coexistência priorizada para ME2 (por exemplo, tags como me2_available ou preferências), a plataforma pode impedir a conversão para ME1 e retornar not_specified. A razão costuma ser a configuração da conta e as preferências comerciais; a conversão para ME1 pode exigir intervenção comercial (KAM) para ajustar as preferências de envio.

RECOMENDAÇÃO
Revise as preferências comerciais e tags do seller; se a conversão falhar, coordene com a equipe comercial para ajustar a configuração de coexistência.
É obrigatório estar no ME2 para que sejam ativadas automaticamente opções como "frete grátis para todo o país"?

Sim: muitas das regras automáticas de exibição e benefícios (por exemplo, "Frete grátis" com benefícios) se aplicam preferencialmente a itens no modo ME2 e dependem também do limite de preço e outras políticas internas. Não é possível forçar via API o benefício global se essas condições não forem atendidas.

RECOMENDAÇÃO
Verifique a elegibilidade para ME2 e os limites exigidos; não tente forçar benefícios via API sem atender às condições do mercado.
É possível forçar via API o frete grátis para todo o país?

Não. A ativação de frete grátis em nível nacional depende de regras automáticas (preço, tipo de logística como ME2) e não pode ser forçada via API sem atender esses requisitos.

RECOMENDAÇÃO
Ajuste preços e logística para atender às condições do mercado; não espere conseguir habilitar frete grátis nacional apenas via API.
Por que configurar shipping.mode = "me1" via API retorna HTTP 200 mas o item permanece com logistic_type "not_specified"?

Ao atualizar o modo de envio de um anúncio para ME1 via PUT /items com shipping.mode = "me1", a API pode retornar uma resposta 200 de sucesso sem que a alteração seja efetivamente aplicada no marketplace. Isso ocorre quando o vendedor tem o Mercado Envios 2 (ME2) habilitado a nível de conta — a plataforma prioriza automaticamente o ME2 e substitui a configuração de ME1 definida via API. Não se trata de um erro de integração, mas de uma regra de negócio a nível de conta que tem precedência sobre as chamadas de API.

RECOMENDACIÓN
Se precisar que a configuração de ME1 tenha efeito para um vendedor, certifique-se de que os ajustes de convivência entre ME1 e ME2 estejam corretamente configurados pelo time comercial ou KAM do vendedor. Tentar forçar ME1 apenas via API não surtirá efeito se o ME2 estiver habilitado a nível de conta.
